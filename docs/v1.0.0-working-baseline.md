# v1.0.0 Working Baseline

This document captures the exact state of every release-critical component at `v1.0.0` — the last known-good release where the desktop app launched correctly on all platforms.

## Bundled Binaries (externalBin)

At v1.0.0, only **two** Go sidecar binaries were bundled:

```json
"externalBin": [
  "binaries/kubilitics-backend",
  "binaries/kcli"
]
```

`kubilitics-ai-server` was **not present** at v1.0.0.

## macOS Signing

| Field | v1.0.0 value |
|-------|-------------|
| `bundle.macOS.entitlements` | `null` (no entitlements file) |
| `bundle.macOS.signingIdentity` | `null` (overridden by CI `--config`) |
| `bundle.macOS.minimumSystemVersion` | `10.13` |
| Info.plist `LSRequiresCarbon` | present (injected by Tauri template) |
| Notarization | `continue-on-error: true` |

At v1.0.0 there was **no entitlements.plist**. The app was signed with the hardened runtime only, no explicit entitlements. This is why it passed notarization — Apple's rules on entitlements only apply to explicit entitlements, not the runtime flag alone.

## Release Workflow (v1.0.0)

### Runners
- macOS: `macos-latest`
- Windows: `windows-latest`
- Linux: `ubuntu-latest`

### macOS Build
```bash
CI=true cargo tauri build \
  --target universal-apple-darwin \
  --bundles app,dmg \
  --config '{"bundle":{"macOS":{"signingIdentity":"<IDENTITY>"}}}'
```

Tauri built both the `.app` AND the `.dmg` in a single step. No post-build plist patching, no manual DMG creation.

### Notarization
- Used `xcrun notarytool submit`
- `continue-on-error: true` — notarization failure did NOT block the release
- No stapler validate step
- No Gatekeeper spctl check

### Signing Flow
1. Tauri builds .app and .dmg with `signingIdentity` passed via `--config`
2. Tauri signs all embedded binaries during the build
3. `xcrun notarytool submit` on the DMG (best-effort, non-fatal)
4. `xcrun stapler staple` on the DMG

No post-build plist modification. No manual re-signing step.

## Startup Sequence

1. `main.rs` → `tauri::Builder::default()` initializes plugins
2. `.setup()` callback fires:
   - `sidecar::start_backend()` — spawns `kubilitics-backend` (fatal if binary missing)
   - *(no brain sidecar at v1.0.0)*
   - `tray::setup_system_tray()` — non-fatal
3. Window opens, frontend loads

## Required Secrets

| Secret | Required | Effect if missing |
|--------|----------|-------------------|
| `APPLE_CERTIFICATE` | No | App unsigned (Gatekeeper dialog shown) |
| `APPLE_CERTIFICATE_PASSWORD` | No | App unsigned |
| `APPLE_SIGNING_IDENTITY` | No | App unsigned |
| `APPLE_ID` | No | Notarization skipped (continue-on-error) |
| `APPLE_PASSWORD` | No | Notarization skipped |
| `APPLE_TEAM_ID` | No | Notarization skipped |
| `TAURI_SIGNING_PRIVATE_KEY` | Yes | Auto-update signatures broken |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Yes | Auto-update signatures broken |

At v1.0.0 the release could complete even without Apple credentials (with a Gatekeeper warning for unsigned app). This is why v1.0.0 appeared to work even in environments without notarization.
